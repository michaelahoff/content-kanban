Native image generation/reference editing and recovery are mandatory before daily-use acceptance; this change does not defer or claim those gates.

## Durable boundary

Schema migration 7 adds card chats, ordered current/previous conversations, immutable submission payloads with mutable delivery status, linked attempts, transcript items, requests and per-field versions. The version triggers observe every existing card mutation, including Set graphs and undo; coarse editor conflict checks remain until #22. Existing cards begin with their current revision as the known field-version baseline.

`store-chat.js` is part of the SQLite store, constructed only by `openStore`. It shares the board transaction and canonical append-only activity log. Native inference never runs inside a transaction. Submission creation inserts the frozen payload and clears only composer text in one transaction; remembered field/role/explicit-image selections remain. Composer saves require their own revision. Repeated POSTs with one browser-generated ID return the original submission and do not clear a newer draft. A deliberate repeated prompt has a different ID and remains valid.

The payload freezes the prompt, labeled saved card fields with field versions, deduplicated exact reference IDs and SHA-256 hashes, provider/model, effective configuration and allowed text fields. The legacy Prompt field is excluded. Explicit manual authority defaults empty; protected card-tool execution comes in #22. Role references resolve from the saved card at queue time. A concurrent card/composer/conversation/settings change while preparing Send rejects the queue write for a fresh preview, rather than capturing mixed inputs.

`chat-service.js` refreshes native discovery for the exact card workspace, compiles effective configuration and prepares references. Idle views and previews do not start Codex. Discover and Send may start its installed app-server. References are verified against frozen hashes and copied read-only into `data/workspaces/<cardId>/references/`; existing matching copies are reused. Damaged source bytes or replaced workspace reference links hold delivery. Gallery/chat image-store unification, output versions and import integrity belong to #23.

## Execution and interruption

`chat-worker.js` wakes after commits and on startup. It claims the oldest eligible submission for each card; a partial unique index enforces one active attempt per card. All independent ready cards can proceed concurrently, with no app concurrency cap. A held earlier submission blocks later submissions on that card. Frozen configuration is checked before opening and again before dispatch. Changed guidance/inventory holds the submission without rewriting it; a changed binding configuration requires explicit empty fresh context. Active work keeps its recorded configuration.

The attempt ID is committed as `dispatching` before transport and supplied as `clientUserMessageId`. The exact native binding/configuration receipt is retained before Send. Follow-ups resume that binding, and supported model changes retain it with a transcript notice. First native creation happens only during Send, including after fresh context. Assistant text is persisted about every 500 ms, at item boundaries and when execution stops. Items are unique by attempt/native item ID. Turn-filtered listeners retain late output without assigning it to a subsequent attempt.

Stop writes interruption intent and invalidates requests atomically, preserving unrelated queued manual submissions. Native interruption happens afterward. Empty fresh context waits for a terminal acknowledgment or reconciliation, retains previous history and clears conversation grants. Old queued/held submissions require explicit cancellation and never target the new conversation. Deleting a card, lane or project writes cancellation/interruption with deletion, blocks new submissions and retains chat/history/files/workspace.

Explicit retry of a terminal failed/interrupted submission creates a linked attempt with the original payload; old conversations and uncertain delivery cannot be retried this way. One-operation command/file approvals can be allowed or denied; input/permission requests are retained and stoppable. Full grant/input support and dynamic card tools belong to #22. No native global permission rules are written.

Startup invalidates pending requests and performs read-only paged history matching by attempt client ID. Known completed/interrupted results are retained without resending. Ambiguous accepted turns and missing matches remain held; an exact missing native binding is shown unavailable and permits the deliberate empty fresh-context path. Independent ready cards need not wait for history reads on another card. Proof-based automatic requeue, deliberate uncertain-delivery resolution, outside-native continuation detection, native image recovery and cursor/offset SSE remain #24. There is no automatic replay of accepted turns.

## Workbench behavior

On wide screens a visible nonmodal workbench keeps a compact board available beside the existing editor and chat. Chat width supports pointer and keyboard resizing. Below 1180px it uses Editor/Chat tabs. Hiding chat restores the floating modal editor. Hidden preference and per-card tab/scroll/preview state use localStorage; unsent composer text/model/references use the server with a 450 ms debounce. Switching/closing/hiding are view operations and never Stop work. Card drafts retain their existing save/conflict behavior.

What will be sent shows selected labeled fields and exact deduplicated references. Earlier submissions retain inspectable frozen context. The browser retains an uncertain Send's ID across reload for a deduplicated retry. Model selection is explicit and unavailable targets are never substituted. Chat snapshots are polled in this milestone; durable streaming belongs to #24. Preliminary activity navigation derives status from rows and uses a static Working indication under reduced motion; cumulative activity behavior is validated in #24.
