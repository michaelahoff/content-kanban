# Library folders, organizing and removal

Implements [#53](https://github.com/michaelahoff/content-kanban/issues/53) against the approved [project-assets specification](https://github.com/michaelahoff/content-kanban/blob/f7149d373a8c8284cdd6b046049d6d54a3c35c57/docs/specs/project-assets.md), acceptance cases 2–4, on top of [uploads and inspection](project-library.md). Selecting Library sources in a card chat, preflight and frozen capture remain [#56](https://github.com/michaelahoff/content-kanban/issues/56); this change supplies the resolution it will use.

## Model

`library_folders` (schema migration `foldersMigration` in `store-retained.js`) holds folder identities: one owning project, an optional parent folder, a name label and `removed_at`. `retained_objects.folder_id` places each Library source at the root (null) or in a folder. Names are labels: `libraryFilename` validates folder names with the same rules as filenames, and no path is ever trusted or used for storage.

- **Folder-local names.** A name is unique among a folder's live files and subfolders (as in a filesystem), including a first upload still in progress. The same filename coexists in different folders. Upload collisions are checked in the destination folder; a subfolder holding the name gives a conflict without `assetId`, so Replace is unavailable and Create new picks a suffix no file or folder holds.
- **Rename and move** (`updateAsset`, `updateFolder`) change only labels and locations, keeping identities, versions and folder contents. A name taken in the destination is refused with `409`, never merged. A folder cannot move into itself or a descendant. The destination must be a live folder of the same project.
- **Removal** (`removeAsset`, `removeFolder`) sets `removed_at`. Folder removal marks the whole subtree — folders and sources, including first uploads in progress, which then never commit — with one timestamp; earlier removals keep their own. Removed sources disappear from listings, collisions and resolution, but `asset()` (with `removedAt`), downloads, verification and repair still work, and `removed()` lists them with their former path. Nothing is restored or revived: an upload to a former name creates a new identity, a retry of an interrupted replacement of a removed file is refused, and a removed folder's name is free for a new folder.
- **Folder drop** uses `ensureFolders({ parentId, names })`: each path segment reuses the live folder of that name, so dropping a folder again merges into it and a retried file finds the same folder. If a file holds a segment's name, the first suffixed name no file holds is used (`refs (1)`), reusing a folder already called that. Each file then publishes atomically through the existing upload with its own operation, collision choice and retry.
- **Resolution** (`resolve(ctx, projectId, [{ kind: 'asset' | 'folder', id }])`) is the seam for remembered selections. Each source reports `resolved`, `removed` or `missing` (foreign, wrong kind or unknown) with its current path. Resolved folders expand recursively over live descendants in relative-path order, compared segment by segment (`comparePaths`); assets are deduplicated by identity at their first position with every selecting source and relative path kept in `selectedBy`. An existing empty folder resolves to zero files. A removed source stays unresolved even after a new source takes its name; nothing is substituted by name.

Every mutation requires an active project inside one transaction (archive refuses it) and appends activity: `asset_renamed`, `asset_moved`, `asset_removed` (entity `asset`) and `folder_created`, `folder_renamed`, `folder_moved`, `folder_removed` (entity `folder`), so other tabs refresh. Maintenance refuses them at the HTTP boundary like every other write.

## HTTP and browser

Routes are listed in the README. Uploads accept `folder=` alongside the existing query-only metadata.

`public/library-format.js` adds `libraryPaths`, `searchLibrary` and `folderHolders`, so the browser computes paths, whole-path search and folder-local collision checks the same way the server does. `public/library.js` adds breadcrumbs and folder tiles, **New folder**, **Upload folder** (`webkitdirectory`), recursive folder drop (`dropLibraryItems` reads directory entries during the drop event; empty directories are created too), whole-path search across folders, a **⋯** menu per tile with one form to rename and move plus **Remove…** with a confirmation, and **Removed files**. Upload rows show each file's relative path; a dropped file's folder is found or created just before it uploads and kept for its retries. The approved prototype's folder tree sidebar is not reproduced; breadcrumbs and folder tiles carry navigation.

## Backup

The manifest inventory gains `folders` (`id`, `projectId`, `parentId`, `name`, `removed`) and each retained version's `folderId`; restore compares both with the bundle's database, so nested structure and removal metadata are verified coverage. Bundles exported before folders have neither field and no folder table, and restore under the older comparison.

## Acceptance evidence

- `node --disable-warning=ExperimentalWarning --test test/library.test.js`: browser path/search/holder helpers; nested folders with folder-local collisions and coexisting filenames across restart; rename/move keep identity and versions, refuse destination conflicts, cycles and foreign folders; removal keeps versions readable, recursive folder removal including an in-progress upload, no revival by name, refused retry after removal; resolution order, overlap provenance, empty folders, replace/move following identity, removed/foreign/wrong-kind sources unresolved after name reuse; folder-drop path reuse, suffixing around a file and idempotent retry; archive refusal of every organizing change; HTTP routes, archive and maintenance refusals; export/restore of folders, locations and removals with tamper detection.
- `npm run test:browser`: New folder, a nested folder drop with an empty directory, re-dropping into the same folder with per-file Create new and Cancel, path search, rename-and-move to the root, a refused name conflict that keeps the form open, recursive folder removal and inspecting removed files.
